# Spec v0.1.12

Source release covering the changes since
[v0.1.11](https://github.com/AI10xDev/spec/releases/tag/v0.1.11), including the
integration at `d407664` and new user documentation. No prebuilt binaries are
attached. Release identity follows Git tags; package manifests remain `0.1.0`.

## Highlights

- Installation guide with a local-editor-first quick start, explicit SSH setup,
  provider configuration, upgrades, and troubleshooting.
- Practical development workflows for scoped specs, verification, follow-ups,
  review/commit handoff, parallel work, recovery, and measured optimization.
- Five-provider AI settings for Azure OpenAI, OpenAI, Claude, OpenRouter, and
  locally served Hugging Face models, with private persisted profiles.
- Focused-sheet autosave, Ctrl/Cmd+Enter to Save & run, source highlighting,
  custom build feedback, and one queued follow-up per running session.
- History-aware planning instructions, Analytics with optional evaluation checks,
  and a task-based rainbow build progress indicator.
- Retained-run browsing, clearer detached/missing-run diagnostics, stale-reader
  recovery, preserved verified terminal state, and 16 spec-run admission slots.
- Independent Performance lifecycle/recovery/cancellation for the existing built
  Gemma RL workflow, plus Explore-backed remote project-name search.
- Supervisor keep-alives instead of overall build deadlines; optimizer provider,
  admission, process cleanup, and report-filtering repairs.
- Source archives exclude historical `.out` logs and `.spec-runs` artifacts.
  Existing tracked artifacts/history are not deleted or rewritten.
- Ignore generated private settings directories, fix test-only Clippy warnings,
  apply Rust formatting, and synchronize the repository-exclusion test with
  actual supervisor lock release rather than attachment exit.

Full changes: https://github.com/AI10xDev/spec/compare/v0.1.11...v0.1.12

## Install Or Upgrade

Follow [Installation](../INSTALLATION.md). For a new local-editor installation:

```sh
git clone --branch v0.1.12 https://github.com/AI10xDev/spec.git
cd spec
unset SPEC_COMMAND
./run.sh --local
```

For remote execution, configure your own SSH target, local key, and remote project
directory; the launcher's default host/key paths are machine-specific. Only the
specification snapshot is uploaded, not other local project files.

Rebuild and restart the actual **local Rust backend** launching SSH runs, then
reconnect with its new token URL. Preserve your workspace, private recovery
records, and settings. Already-running remote supervisors retain their old
behavior; neither the execution engine nor model runtimes are upgraded by this
release. Do not start duplicate work while a previous run is unresolved.

not a live SSH host, paid model API, GPU workload, or production deployment.
The npm fallback, real microphone/media providers, non-Chromium browsers, and
native OS-menu/real IME behavior were not independently validated for this release.

## Limits And Safety

- Linux source installation; no Windows support, validated macOS build, automatic
  service deployment, or bundled execution engine/model weights.
- SSH and model tools are trusted, unsandboxed execution with automatic approval
  requested. They can change files, access credentials/network, and incur costs.
- Performance requires an existing built Gemma RL project and real prerequisites;
  it does not install the workflow or substitute the distillation pipeline.
- Continued builds do not receive editor changes. Queued feedback requires the
  browser page to remain open and confirmed successful completion before delivery.
- Missing status and SSH attachment exit 255 do not establish remote completion.
  A successful CLI exit does not prove implementation correctness.
- No overall build/optimizer runtime cap. Keep-alives indicate liveness; measured
  optimization plateaus do not establish a global optimum or positive improvement.
- Historical review findings and deployment evidence are not blanket-closed by
  this release. See the [dated review](../CODE_REVIEW_2026-10-28.md) and current
  workflow documentation for scope and evidence limits.
